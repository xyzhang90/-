## Part 1：实战前的热身

### 1.1 类别特征编码

**独热编码（One-Hot Encoding）**：把一个有 N 个类别的特征拆成 N 列 0/1，每个样本只在自己所属的那一类对应的列上取 1，其余都是 0。

比如某个特征有 {A, B, C} 三类，3 个样本编码后就是：

| 原始值 | A | B | C |
|---|---|---|---|
| A | 1 | 0 | 0 |
| B | 0 | 1 | 0 |
| C | 0 | 0 | 1 |

**标签编码（Label Encoding）**：直接把每个类别映射成一个整数，比如 A→0, B→1, C→2。

**两者区别**：One-Hot 之后每一列都是独立的 0/1，类别之间没有谁大谁小；Label Encoding 相当于给类别排了个 0、1、2 的序，但这个数字大小本身是没意义的。

**神经网络为什么更常用 One-Hot**：这一点我一开始没想通，后来看了梯度下降才反应过来——神经网络是按数值大小更新权重的，如果用 Label Encoding，网络会真的以为 2 比 1"大"，把这个不存在的顺序学进去，梯度方向就被带偏了。One-Hot 各列正交，谁也不压谁，就不会有这个问题。

### 1.2 数据标准化

**为什么 MLP 对特征尺度敏感**：这次数据里 Age 大概在 30~80，Cholesterol 却能到 600 多，如果直接喂进去，Cholesterol 那一维权重的梯度天然就比 Age 大几十倍，更新方向会被大数值特征牵着走，小特征学不到东西，收敛也慢。标准化之后大家都在一个量级，梯度更新才均衡。

- **Z-Score 标准化（StandardScaler）**：$z = \dfrac{x - \mu}{\sigma}$，$\mu$ 和 $\sigma$ 都是在训练集上算的，做完之后这一列均值 0、方差 1。
- **Min-Max 归一化**：$x' = \dfrac{x - \min}{\max - \min}$，把数据线性压到 [0, 1]。

**测试集怎么办**：scaler 在训练集上 `fit` 好之后，测试集只能 `transform`，**绝对不能在测试集上重新 `fit`**。这个坑我第一次做 Kaggle 类比赛的时候踩过——重新 fit 等于偷看了测试集的均值方差，最后线上分数虚高，线下验证对不上。这就是所谓的数据泄漏（data leakage）。

### 1.3 训练/验证/测试

- **训练集（Train）**：真的拿去算梯度、更新权重的数据。
- **验证集（Validation）**：训练过程中拿来看效果、调超参数用的，不参与权重更新。
- **测试集（Test）**：所有东西都定下来之后才最后碰一次，用来报告真实泛化能力。

**为什么不能拿测试集调参**：测试集代表的是"模型从没见过的新数据"。如果一边调参一边看测试集分数，相当于考试的时候提前看了答案，分数再高也不说明模型真的好。

**为什么不能直接拿训练集当验证集**：模型已经把训练集背下来了，训练集上的准确率本来就虚高，根本看不出有没有过拟合。

**只有一个 train.csv 怎么办**：从 train.csv 里再切一块出来当验证集。我这里用的是 `train_test_split(test_size=0.15, random_state=42, stratify=y)`，`stratify=y` 是为了切出来的正负样本比例和原数据一致，不然万一验证集里全是正例，指标就没法看了。

### 1.4 分类任务的评估

**准确率在类别不均衡时的坑**：假设数据集里 99% 都是负样本，模型啥也不学、全部预测成负类，准确率也有 99%，看起来很漂亮，但其实一个正样本都没抓出来。所以数据不均衡的时候不能只看准确率。

- **精确率（Precision）**：预测为正的样本里，真的是正的比例，$P = \dfrac{TP}{TP+FP}$。可以理解成"模型喊狼来了的时候，真有狼的概率"。
- **召回率（Recall）**：所有真的正样本里，被模型抓出来的比例，$R = \dfrac{TP}{TP+FN}$。
- **F1-Score**：精确率和召回率的调和平均，$F1 = \dfrac{2PR}{P+R}$，两个都想高的时候用它折中。

**混淆矩阵四格**：

| | 预测为正 | 预测为负 |
|---|---|---|
| 实际为正 | TP（真正例） | FN（漏报） |
| 实际为负 | FP（误报） | TN（真负例） |

**ROC 曲线和 AUC**：ROC 横轴是假正率 FPR，纵轴是真正率 TPR，画的是不同分类阈值下模型的表现；AUC 就是这条曲线下的面积，越接近 1 说明模型把正负样本分开的能力越强。

### 1.5 小批量训练

**为什么用 Mini-Batch**：全量 Batch GD 一次跑完整份数据，梯度是稳，但 800 多条数据还好，到了大数据集根本扛不住内存，而且容易卡在一个地方出不来；纯 SGD 一次只喂一条样本，更新倒是快，但梯度噪声太大，loss 曲线抖得厉害。Mini-Batch 相当于折中：一次喂几十条，梯度没那么抖，又能吃得下矩阵运算的并行加速，实际几乎都用它。

**DataLoader 参数**：
- `batch_size`：每个小批量塞多少条样本，我这里取了 32。
- `shuffle`：每个 epoch 开始要不要打乱顺序。训练集一定要 `shuffle=True`，不然模型可能会学到"批次之间的顺序"这种假规律；验证集 `shuffle=False` 就行，因为评估不关心顺序，而且不打乱结果更好复现。

## Part 6：思考题

### 思考题 1：类别特征处理方式对比

我对 Sex、ChestPainType、RestingECG、ExerciseAngina、ST_Slope 这 5 个类别特征用的是 **One-Hot 编码**（sklearn 的 `OneHotEncoder`，`handle_unknown='ignore'`，防止测试集出现训练集里没见过的类别直接报错）。

为了回答这道题，我又把类别特征换成 **Label Encoding** 跑了一遍完全相同的网络结构和超参数，对比结果：

| 编码方式 | 最终验证准确率 | 最佳验证准确率 |
|---|---|---|
| One-Hot Encoding | **0.8374** | 0.8618 |
| Label Encoding | 0.8293 | 0.8618 |

两次最佳准确率刚好一样，但 One-Hot 的最终（第 100 个 epoch）准确率高一点点。加上 One-Hot 不会给类别凭空加顺序关系，最后还是选了 One-Hot。

### 思考题 2：过拟合现象与缓解

**我确实看到了过拟合**。基线配置下，训练损失从 0.36 一路降到 0.225，可验证损失大概在 epoch 30 之后就不降反升，最后涨到 0.454，验证准确率一直在 0.82~0.86 之间晃悠不再往上走——训练和验证的差距越拉越大，就是典型的过拟合信号。

**我用的缓解手段**：

1. **Dropout(0.3)**：每个隐藏层后面接一个 Dropout，训练时随机丢掉 30% 的神经元，强迫网络不要太依赖某几个神经元。我专门做了一组对比（其他配置完全一样，只把 Dropout 去掉）：

   | 配置 | 训练损失(末) | 验证损失(末) | 最终验证准确率 |
   |---|---|---|---|
   | 无 Dropout | 0.039 | **0.902** | 0.8211 |
   | Dropout(0.3) | 0.225 | **0.454** | **0.8374** |

   没加 Dropout 的时候训练损失直接干到 0.039，验证损失却飙到 0.902，模型基本把训练集背下来了；加上 Dropout 之后验证损失几乎砍半，准确率也涨了 1.6 个百分点左右，效果很明显。

2. **BatchNorm**：每个隐藏层后面接 BatchNorm，一方面加速收敛，另一方面也有一点正则化的作用。

3. 权重衰减和早停这次没加。数据一共才 818 条，过拟合程度不算特别严重，Dropout 已经够压住了；而且我固定了随机种子 42，每次跑结果都一样，方便对比实验。以后数据再多一点会考虑加 Early Stopping。

### 思考题 3：特征重要性

**定量方法**：我用了随机森林（300 棵树）在全部训练数据上拟合，直接读 `feature_importances_`。随机森林在分裂节点的时候会统计每个特征被拿来分裂后纯度提升了多少，累加起来就是这个特征的重要性，算起来很快。

**排序结果**（前 5 和最后 2 名，完整图见 `feature_importance.png`）：

| 排名 | 特征 | 重要性 |
|---|---|---|
| 1 | ST_Slope_Up | 0.1375 |
| 2 | ST_Slope_Flat | 0.1022 |
| 3 | Cholesterol | 0.0953 |
| 4 | Oldpeak | 0.0915 |
| 5 | MaxHR | 0.0891 |
| … | … | … |
| 18 | ST_Slope_Down | 0.0063 |
| 19 | ChestPainType_TA | 0.0055 |

**如果只能删一个**：我会删 **ChestPainType_TA**，它的重要性排倒数第一（0.0055），而且 TA 这个类别本来就只有 38 条样本，对模型贡献最小，删了对结果影响应该也最小。

**其他方法**：排列重要性（Permutation Importance，把某一列打乱看掉点多少）和 SHAP 值也能做，而且更贴近 MLP 本身，这次时间有限只跑了随机森林，后面可以补上交叉验证。

## Part 7：报告

### 1. 数据探索

- **数据规模**：train.csv 818 行 × 13 列（含 id 和标签 HeartDisease），test.csv 100 行 × 12 列；`isna().sum()` 跑下来没有缺失值，省了一大块清洗工作。
- **类别平衡**：HeartDisease=1（有心脏病）450 条占 **55.0%**，=0（正常）368 条占 45.0%，正负样本基本对半开，可以直接用准确率当主要指标。
- **数值特征大致情况**：Age 29~77（均值 53.5）；RestingBP 0~200（均值 132.6，居然有 0，应该是缺失值被填成 0 了，这次没动它）；Cholesterol 0~603（均值 198.5，右偏挺明显）；MaxHR 60~202（均值 136.3）；Oldpeak -2.6~6.2（均值 0.88）；FastingBS 是 0/1 二值，23% 为 1。
- **类别特征分布**：Sex 男 639 / 女 179；ChestPainType 里 ASY 448 条最多，TA 只有 38 条；RestingECG 里 Normal 500、ST 159、LVH 159。
- **EDA 小结**：没缺失、标签均衡；类别特征分布很不均匀（One-Hot 之后会有几列特别稀疏）；数值特征之间量级差得远（Cholesterol 几百、Oldpeak 个位数），**必须标准化**。

### 2. 预处理方案

- **数值特征**（Age、RestingBP、Cholesterol、MaxHR、Oldpeak、FastingBS）：用 `StandardScaler` 做 Z-Score。
- **类别特征**（Sex、ChestPainType、RestingECG、ExerciseAngina、ST_Slope）：用 `OneHotEncoder` 做独热，`handle_unknown='ignore'`。
- 用 `ColumnTransformer` 把上面两步捆在一起跑，**编码器只在训练集上 `fit`，测试集只 `transform`**（这条是 Part 1.2 踩坑换来的教训）。
- 划分：`train_test_split(test_size=0.15, random_state=42, stratify=y)`，切完训练集 695 条、验证集 123 条，在题目建议的 10%~20% 区间里。
- 预处理完特征一共 20 维。

### 3. 模型结构

`HeartDiseaseClassifier`（自己写的 MLP，3 个隐藏层 + BatchNorm + Dropout）：

```
Input(20) → Linear(20,64) → BatchNorm1d → ReLU → Dropout(0.3)
         → Linear(64,32)  → BatchNorm1d → ReLU → Dropout(0.3)
         → Linear(32,16)  → BatchNorm1d → ReLU → Dropout(0.3)
         → Linear(16,1)   → 输出 1 个 logit
```

- **损失函数**：`BCEWithLogitsLoss`。二分类就用它，模型最后不用自己加 Sigmoid，损失函数内部会帮你做，数值上更稳。
- **优化器**：Adam，学习率 1e-3。
- **为什么这么设计**：总共就 818 条数据、20 个特征，网络太大肯定过拟合，3 层 64-32-16 我感觉刚好——容量够但不臃肿。BatchNorm 用来稳住训练，Dropout 压过拟合（对比实验见思考题 2）。

### 4. 训练过程

- **超参数**：epochs=100，lr=1e-3，batch_size=32，验证集 15%，随机种子 42。
- **曲线**：见 `training_curves.png`。训练 loss 一路降到 0.225；验证 loss 先降后升（大概 epoch 30 开始抬头），有点过拟合的意思；验证准确率在 0.82~0.86 之间震荡。
- **最终验证集结果**：**Accuracy = 0.8374**。分类报告：

| 类别 | Precision | Recall | F1 | 样本数 |
|---|---|---|---|---|
| 0（无心脏病） | 0.84 | 0.78 | 0.81 | 55 |
| 1（有心脏病） | 0.83 | 0.88 | 0.86 | 68 |

- 混淆矩阵见 `confusion_matrix.png`（TP=60, FN=8, FP=12, TN=43）。
- 测试集预测导出 `submission.csv`，id + HeartDisease 两列共 100 行，格式和 `example_submission.csv` 对齐。

### 5. 改进策略（含超参数实验记录）

基线（OneHot + Dropout 0.3 + lr=1e-3）跑通之后，我固定随机种子和数据划分，又做了 4 组对比实验：

| 实验 | 配置 | 最终验证准确率 | 最佳验证准确率 | 训练损失(末) | 验证损失(末) |
|---|---|---|---|---|---|
| 基线 | OneHot + Dropout0.3 + lr=1e-3 | **0.8374** | 0.8618 | 0.2250 | 0.4541 |
| ① 去掉正则化 | Dropout=0 | 0.8211 | 0.8455 | 0.0390 | 0.9021 |
| ② 换 Label 编码 | LabelEncoding + Dropout0.3 | 0.8293 | 0.8618 | 0.2593 | 0.4167 |
| ③ 大学习率 | lr=1e-2 | 0.8211 | 0.8537 | 0.2089 | 0.5444 |
| ④ 小学习率 | lr=1e-4 | 0.8374 | 0.8618 | 0.3543 | 0.3646 |

**我的分析**：
- **Dropout 作用最明显**：去掉之后直接训练损失 0.039 / 验证损失 0.902，严重过拟合；加上之后验证损失砍半，准确率涨了 1.6 个点。
- **One-Hot 略好于 Label 编码**：最终 0.8374 vs 0.8293，差距不大，但 One-Hot 理论上更干净。
- **学习率 1e-3 和 1e-4 结果差不多**（都是 0.8374），1e-2 太大，训练抖得厉害，准确率反而掉。
- 最后就保留了基线配置，简单、效果也够用。

### 6. 收获与反思

- 第一次完整走完一个真实分类任务的流水线：EDA → 预处理 → 搭模型 → 训练 → 评估 → 出提交文件，中间每一步为什么要做，比上课的时候清楚多了。
- 对"数据泄漏"这件事有了肌肉记忆：scaler 和 encoder 只能在训练集上 fit，测试集乖乖 transform，不能图省事重新 fit。
- 亲眼看到小数据上正则化有多重要：没 Dropout 的时候训练 loss 几乎归零，验证 loss 却翻倍，模型就是把训练题背下来了。
- 学会用随机森林的 feature_importances_ 给特征排序，"哪个特征重要"从拍脑袋变成了有数字支撑。
- **不足**：数据量太小，验证集只有 123 条，结果会有波动，后面应该做 K 折交叉验证；可以加上 Early Stopping 自动停；特征重要性也想用 SHAP 再交叉验证一下。
